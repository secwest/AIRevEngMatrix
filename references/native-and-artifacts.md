# Native artifacts and bytecode

Native analysis combines raw structure from format parsers with interpretations from installed analysis engines. Each decisive fact retains its producer and source location. Multi-component joins and portable provenance use the [graph and evidence conventions](evidence-and-runtime.md).

Use the [language/decompiler taxonomy](language-decompilation.md) for engine selection and the [Rust guide](rust-reverse-engineering.md) for Rust constructs and compiler metadata. [Binary transformations](binary-transformations.md) covers unpacking, assembly, rebuilding and snippet emulation; [platform analysis](platform-and-kernel.md) covers kernel, driver, eBPF and GPU boundaries.

Environment-specific native workflows cover [C/C++](cpp-reverse-engineering.md), [Apple Swift/Objective-C](apple-reverse-engineering.md), [Go](go-reverse-engineering.md), and [scientific/legacy compilers](specialized-development-environments.md).

## Native adapter details

For a decompiler API, first probe edition/version and whether batch export is available. Open an immutable copy or a database tied to the original digest. Ask for only the data required by the current question; deep whole-program analysis can be expensive. Serialize exact engine addresses as strings, instruction bytes, symbol names, function ranges, and references before generating a narrative. A function's callers and callees include the edge type and the instruction address where that edge originated. Pseudocode is a producer report, not original source.

Build function, string, symbol and cross-reference search as indexed queries over the exported database. Call-path searches have explicit depth and node caps. Direct call edges establish static relationships; a chain of such edges can still be infeasible under the program's branch conditions or state. Callbacks, tail calls, exceptions, and asynchronous dispatch need their own edge semantics. Unresolved dispatch yields a partial path. Value tracing requires data-flow evidence from SSA/decompiler output or a bounded runtime trace; a string match is only a lead.

For one instruction, return exact address, bytes, mnemonic, ordered operands, control-flow class and typed references; distinguish data, undecodable bytes and an interior address. For one recovered data type, export database path, size, alignment, packing, fields/bitfields, enum values and child type IDs; source-level type meaning may remain uncertain. A loaded-image check for DOS MZ or selected COM images can compare immutable source bytes with the provider's loaded image, header/module mappings, relocation effects and entry state; preserve overlay and uninitialized coverage gaps. Do not generalize it to unsupported formats.

An Objective-C message send can resolve to multiple implementations. Recover receiver type constraints, selector, category/class metadata, and inheritance before naming a target. Swift demangling is a naming aid; verify type ownership in metadata or code. For native UI action tracing, join interface-builder outlet/action wiring, accessibility identifiers, runtime event, and selector/function evidence where available. Report which link is inferred.

Function-body ranges and their endpoint conventions are explicit. A function can have disjoint ranges, so enclosing span and body byte count differ. API/dispatch analysis retains jump-table data locations, index transformations, case-to-target associations, and a separately evidenced default branch. An unresolved case value does not establish the default.

## Navigation and annotation operations

Navigation queries read the selected document, cursor, containing procedure, bookmarks, and adjacent analyzed objects. A requested destination can snap to an object's start; the returned coordinate records what actually happened. Headless workflows use explicit addresses. Function containment comes from analyzed body ranges, not proximity to a symbol. Search preserves literal queries unless regex is requested, and regex work has a cancellation deadline.

Annotation edits have an explicit database and persistence scope. A rename or comment update validates the selected address, engine constraints, and name ownership before writing, then reads back the result. Empty text clears only the selected comment channel. Batch renames define how selected names may move or swap and return per-item outcomes. A grouped function rename/comment edit uses an engine transaction when available; otherwise the adapter cannot claim atomicity and must retain enough prior state to report or undo partial changes. Bookmarks are navigation metadata. Annotation changes never establish a modification to the original executable bytes.

## Native UI scenarios

A scenario binds the artifact to an exact process and window, records a baseline accessibility tree or screenshot, and applies named steps to uniquely selected elements. Typical steps are press, increment/decrement, text entry, and bounded waits. Each step records the selected element, before/after state, action error and capture error independently. Window replacement or process exit invalidates the old selection instead of silently widening it. The result states which app effects were observable, which permissions were available, and whether any restoration was requested and achieved.

Call observation separately declares launch or attach mode, owned processes, selected breakpoints, ABI, event/time limits and cleanup. Function-entry register values require ABI-aware interpretation before being called arguments. Unresolved breakpoints, attach gaps and lost hits remain explicit; debugger cleanup applies only to the declared ownership scope.

## Structured Apple resources

A keyed-archive parser preserves the original object table, UID references, class descriptors and named roots. Shared references and cycles require stable object IDs and a visited set; deserializing into live platform objects can execute behavior and is unnecessary for static inspection. Compiled UI connection graphs retain outlet/action IDs and unresolved classes. Asset catalog metadata identifies catalogs and renditions but does not establish that rendition bytes were extracted. Loader resolution uses the executable root, loader location, architecture and ordered rpath context for each process; out-of-scope system paths stay unresolved until matching evidence is supplied.

## Extraction and layout details

For Mach-O fat binaries, parse the fat table and keep `slice_offset`, `slice_size`, CPU type/subtype and the thin Mach-O's own coordinates. A section's original-file offset equals slice offset plus thin-section offset only when that range is validated in the original file. PE resource trees, .NET directories and overlay bytes need their own bounds checks. Archive extraction should not follow paths outside the chosen output directory; output filenames may need collision-safe normalization while preserving original member names in metadata.

Address mapping is partial. ELF load segments distinguish file size from memory size, and `.bss` can occupy memory without bytes in the file. Similar zero-fill and virtual-only regions occur in other executable formats. A mapper returns the backing kind and a file offset only where one exists; a synthesized zero is distinct from a byte read from the artifact. Runtime mappings additionally depend on the format's load bias or slide. ELF loading details are specified in the [System V ABI](https://gabi.xinuos.com/elf/07-pheader.html).

Extraction preserves member type, original path, link target, size, mode, and relevant metadata even when the host cannot reproduce them. Case collisions, Windows path semantics, hard links, and device nodes require explicit handling. Potentially unsafe filesystem entries can be represented in a manifest without creating them on the host. This retains startup and permission evidence while keeping the extraction inside its destination.

For packed or transformed code, identify compression/encryption indicators from structure and entry behavior, then document each transformation step. High entropy alone is not proof of packing. If a runtime dump is needed, use a controlled run and capture the mapped region with its load address, protection, time and parent image identity. Dumped bytes are a derived artifact. A raw code region can be analyzed with its memory map and architecture even when it has no executable header. Rebuilding a loadable file is a separate operation whose headers, imports, relocations, and entry point require validation; missing information remains explicit.

PE resource inspection walks the type/name/language tree and returns each leaf's RVA, file offset, code page, size and content digest, with malformed branches reported explicitly. Binary layout inspection includes linked addresses, relocation table identities (including encoded RELR where present), imports/dependencies, interpreter, raw name bytes and static mitigation inferences. Do not infer runtime library paths or complete relocation coverage from a file layout alone.

Artifact, function, bundle and behavior comparisons use a tiered method: byte digests and member manifests; normalized sections/imports/exports/resources; function signatures/CFG/instruction or AST shapes; then observed scenario results. Return exact changes, plausible semantic changes, and unmatched regions separately. A changed hash does not itself identify changed behavior.

## Acceptance examples

- A known universal Mach-O reports both slices and correct original-file offsets for a selected section.
- An imported function's call site points to the expected import entry, and a call-path query cites that instruction.
- A bundle extraction rehashes to the same member bytes and cannot escape the output directory.
- A crash module build ID mismatch is surfaced rather than silently symbolized against the wrong file.
- A valid zero-fill memory range has no invented file offset; a file-backed range maps back to its original bytes.
- A call graph containing incompatible branch conditions is reported as a static path without claiming that one execution traverses it.
